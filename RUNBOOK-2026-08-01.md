> **`--max-calls=800`, not 2000.** Airtable Free allows **1,000 API calls per
> month per workspace**, and that is the entire budget for August. A ceiling of
> 2,000 sits above the real cap, so it would never fire — Airtable would
> hard-block first, exactly as it did on 27 July, and the remaining bases would
> be stranded until 1 September. 800 leaves genuine headroom and makes the stop
> protective rather than decorative.
>
> Budget estimate: 95 Airtable tables across the seven bases, less the 16
> already mirrored that `--only-missing` skips, so roughly 79 tables. One call
> each plus one per additional 100 records puts a full run near 150 calls. The
> 800 ceiling is comfortable.
>
> **Do not browse the OS while the sync runs.** Any page hitting a table that is
> not yet mirrored still calls Airtable and competes for the same 1,000. Once a
> table has one successful SyncRun it serves from Postgres and costs nothing.

gain their full cycle counts, and affiliate reconciliation gains its base.

### 2.2 Derive subscriptions from order history

Needs **no Recharge API key**. Every signal is already on the Shopify order:

| Signal | Meaning |
|---|---|
| `tags` | `Subscription`, `Subscription First Order`, `Subscription Recurring Order` |
| `sourceName` | `subscription_contract_checkout_one` = recurring, `web` = first |
| `app.name` | `Recharge Subscriptions` |
| `lineItems.sellingPlan.name` | cadence and discount, e.g. "1 month subscription with 10% discount" |
| `customer.tags` | `Active Subscriber` / `Inactive Subscriber` |
| `customer.numberOfOrders` | lifetime cycles |

Gives subscriber roster, per-SKU mix, first-vs-recurring split, discount cost,
churn state and cycle counts. Write to native `os:` tables — the existing
`UK.SUBSCRIPTIONS`, `UK.SUBSCRIBERS` and `UK.CUSTOMERS` Airtable tables are all
empty and a sync would wipe anything put in them.

**Not derivable from orders:** next billing date, upcoming charge value, paused
subscriptions, cancellation reasons, forward MRR. Those need the
`read_own_subscription_contracts` scope (`subscriptionContracts` is currently
access-denied) or the Recharge API.

### 2.3 GoAffPro — blocked on the token

Base `https://api.goaffpro.com/v1/`, token from Settings > Advanced > Access
Tokens. Admin endpoints: affiliates, per-affiliate commissions, coupons,
referral codes and tags, orders.

**Why this is not just a reporting tab:** affiliate commission is a real cost
that scales with revenue and appears **nowhere** in the current UK P&L. The
£3,549.90 July contribution on `/report/shopify-uk` is overstated by whatever
affiliates were paid. Connecting GoAffPro converts that from an invisible
omission into an ACTUAL cost line in `UK.COST_MODEL`.

Cross-check: GoAffPro coupons and referral codes map to `Discount Code` on
`UK.ORDERS`, so affiliate revenue reconciles from two independent directions.

### 2.4 Simple Bundles double-counting

Bundle orders explode into component line items carrying `_sb_bundle_title` /
`_sb_bundle_group` / `_sb_bundle_variant_id_qty` (see order #1484, "Gout
Support"). Components bill separately, so per-SKU revenue and margin
double-count against the bundle price unless handled. Decide the treatment:
report at bundle level, or allocate the bundle price across components by cost.
